# 6.5 优先队列

本节整理《算法导论》第三版习题 6.5-1 至 6.5-9。先回顾优先队列的基本操作，再记录执行过程、伪代码、正确性证明和复杂度。题意以学习讨论中的简述为主，伪代码采用与教材等价的写法，不包含章末思考题。

## 小节回顾

### 从堆到优先队列

优先队列维护一组带关键字的元素，用关键字决定取出顺序。最大优先队列取关键字最大的元素，最小优先队列取关键字最小的元素。

堆是实现优先队列的一种方式。最大堆只要求父结点不小于孩子，并不要求数组整体有序。

| 最大优先队列 | 最小优先队列 | 用二叉堆实现的时间上界 |
|---|---|---|
| MAXIMUM：查看最大值 | MINIMUM：查看最小值 | $\Theta(1)$ |
| EXTRACT-MAX：删除并返回最大值 | EXTRACT-MIN：删除并返回最小值 | $O(\lg n)$ |
| INCREASE-KEY：增大已有关键字 | DECREASE-KEY：减小已有关键字 | $O(\lg n)$ |
| INSERT：插入元素 | INSERT：插入元素 | $O(\lg n)$ |

表中查看操作假设堆非空；插入假设底层数组有可用容量，或由实现另行处理扩容。空堆和单元素堆的操作耗时为常数，表中的对数界按通常的渐近意义理解。

### 向上调整与向下调整

- 取出堆顶：用末尾元素补根，缩小堆，再向下调整。
- 最大堆增大关键字：与孩子的关系仍正确，但可能超过父结点，因此向上调整。
- 最小堆减小关键字：与孩子的关系仍正确，但可能小于父结点，因此向上调整。

最大优先队列的两个相关过程如下，数组下标从 1 开始：

```text
HEAP-INCREASE-KEY(A, i, key)
    if key < A[i]
        error "新关键字小于原关键字"
    A[i] = key
    while i > 1 and A[PARENT(i)] < A[i]
        exchange A[i] with A[PARENT(i)]
        i = PARENT(i)

MAX-HEAP-INSERT(A, key)
    A.heap-size = A.heap-size + 1
    A[A.heap-size] = −∞
    HEAP-INCREASE-KEY(A, A.heap-size, key)
```

$\operatorname{PARENT}(i)=\lfloor i/2\rfloor$。向上调整不一定到根；遇到不小于当前元素的父结点就停止。

### 与前几节的联系

HEAP-EXTRACT-MAX 复用了 MAX-HEAPIFY，其过程类似堆排序的一轮。区别在于：堆排序把最大值放入数组末尾的已排序区域；优先队列删除并返回最大值，让剩余元素继续构成堆，以支持后续操作。

本节把已有堆操作组织成可持续插入、取出和修改关键字的数据结构。

## 6.5-1 删除并返回最大元素

**题意：** 展示 HEAP-EXTRACT-MAX 在最大堆

$$
A=\langle15,13,9,5,12,8,7,4,0,6,2,1\rangle
$$

上的操作过程。

先保存堆顶 15，再把最后的 1 放到根，将堆大小从 12 减为 11，最后调用 MAX-HEAPIFY(A, 1)。下表只列仍属于堆的有效区域。

| 步骤 | 有效堆数组 |
|---|---|
| 末尾元素补根，缩小堆 | `1, 13, 9, 5, 12, 8, 7, 4, 0, 6, 2` |
| 1 与较大的孩子 13 交换 | `13, 1, 9, 5, 12, 8, 7, 4, 0, 6, 2` |
| 1 与较大的孩子 12 交换 | `13, 12, 9, 5, 1, 8, 7, 4, 0, 6, 2` |
| 1 与较大的孩子 6 交换 | `13, 12, 9, 5, 6, 8, 7, 4, 0, 1, 2` |

1 沿下标 $1\to2\to5\to10$ 下移，到达叶结点后停止。返回值为 15，剩余最大堆为

$$
\boxed{\langle13,12,9,5,6,8,7,4,0,1,2\rangle.}
$$

**要点：** 向下调整时，应选择两个孩子中较大的那个交换。一次取最大值的时间上界为 $O(\lg n)$。

## 6.5-2 插入新元素

**题意：** 在上一题给出的原始最大堆上执行 MAX-HEAP-INSERT(A, 10)。两题分别从原始堆开始，不接着上一题的结果操作。

将堆大小增为 13，在新叶结点处放入 $-\infty$，再调用 HEAP-INCREASE-KEY 将其提高到 10。

| 步骤 | 有效堆数组 |
|---|---|
| 新增下标 13，初始值为 $-\infty$ | `15, 13, 9, 5, 12, 8, 7, 4, 0, 6, 2, 1, −∞` |
| 将新关键字改为 10 | `15, 13, 9, 5, 12, 8, 7, 4, 0, 6, 2, 1, 10` |
| 与下标 6 的父结点 8 交换 | `15, 13, 9, 5, 12, 10, 7, 4, 0, 6, 2, 1, 8` |
| 与下标 3 的父结点 9 交换 | `15, 13, 10, 5, 12, 9, 7, 4, 0, 6, 2, 1, 8` |

此时父结点为根 15，不小于 10，因此停止。最终结果为

$$
\boxed{\langle15,13,10,5,12,9,7,4,0,6,2,1,8\rangle.}
$$

10 沿下标 $13\to6\to3$ 上移。新增位置必须在末尾，以保持完全二叉树形状；最大堆性质通过向上调整恢复。

## 6.5-3 用最小堆实现最小优先队列

**题意：** 写出 HEAP-MINIMUM、HEAP-EXTRACT-MIN、HEAP-DECREASE-KEY 和 MIN-HEAP-INSERT。

最小堆要求父结点不大于孩子。相对于最大堆，大小比较方向反转；取出堆顶仍向下调整，减小关键字则向上调整。

```text
HEAP-MINIMUM(A)
    // 假设堆非空
    return A[1]

HEAP-EXTRACT-MIN(A)
    if A.heap-size < 1
        error "堆下溢"
    min = A[1]
    A[1] = A[A.heap-size]
    A.heap-size = A.heap-size - 1
    MIN-HEAPIFY(A, 1)
    return min

HEAP-DECREASE-KEY(A, i, key)
    if key > A[i]
        error "新关键字大于原关键字"
    A[i] = key
    while i > 1 and A[PARENT(i)] > A[i]
        exchange A[i] with A[PARENT(i)]
        i = PARENT(i)

MIN-HEAP-INSERT(A, key)
    A.heap-size = A.heap-size + 1
    A[A.heap-size] = +∞
    HEAP-DECREASE-KEY(A, A.heap-size, key)
```

其中 MIN-HEAPIFY 是 MAX-HEAPIFY 的对称版本，下面补出其等价写法。有效堆为空时立即返回，也覆盖取出最后一个元素的情形。

```text
MIN-HEAPIFY(A, i)
    if i > A.heap-size
        return
    l = 2 * i
    r = 2 * i + 1
    smallest = i
    if l <= A.heap-size and A[l] < A[smallest]
        smallest = l
    if r <= A.heap-size and A[r] < A[smallest]
        smallest = r
    if smallest != i
        exchange A[i] with A[smallest]
        MIN-HEAPIFY(A, smallest)
```

HEAP-MINIMUM 耗时 $\Theta(1)$，其余三种队列操作的时间上界均为 $O(\lg n)$。使用 $+\infty$ 是为了保证插入时可以将初始关键字减小到任意目标值。

## 6.5-4 为什么先设置为负无穷

**题意：** MAX-HEAP-INSERT 为什么先将新叶结点设为 $-\infty$，随后又将其增大到目标值？

这一步使调用 HEAP-INCREASE-KEY 的前提得到保证：

1. 新叶结点的值为 $-\infty$，不大于父结点，添加它后仍是最大堆。
2. 待插入的 key 不小于 $-\infty$，满足新关键字不小于旧关键字的要求。

如果新增位置残留了任意旧值，例如 100，而待插入值是 10，直接调用 HEAP-INCREASE-KEY 可能触发其参数检查。

**结论：** $-\infty$ 是为了复用已有过程而设置的初始值，插入的核心仍是向上调整。若单独实现插入，可以保存新值、逐个下移较小的父结点，最后填入新值，不必实际存放 $-\infty$。这也是 02lecture 中插入过程的思路。

## 6.5-5 用循环不变式证明增大关键字操作正确

**题意：** 假设调用前 A 是最大堆，利用给定循环不变式证明 HEAP-INCREASE-KEY 正确。

**循环不变式：** 每次 while 循环开始时，A 的有效区域满足最大堆性质，唯一可能的违背是当前 A[i] 大于其父结点。

### 初始化

将 A[i] 的关键字增大后，它仍不小于原来的孩子。其余位置没有变化，因此只有它与父结点之间可能违背最大堆性质，不变式成立。

### 保持

设正在上移的新关键字为 x，当前父结点的值为 p。循环条件成立时 x > p，交换二者。

- x 上移后不小于两个孩子：一个孩子是 p，另一个是原来 p 的另一个孩子；交换前 p 不小于这个另一个孩子，而 x > p。
- p 下移后仍不小于其新位置的孩子。为明确这一点，可跟踪原始堆：x 沿原位置到根的路径上移，每次只是把该路径上的一个祖先旧值下移一层；p 下方的孩子值原本都属于 p 的后代，因此不大于 p。
- 其余父子关系没有改变。

于是，唯一可能的新违背是上移后的 x 大于其新父结点。执行 i = PARENT(i) 后，i 跟踪 x 的新位置，不变式继续成立。

### 终止

每次迭代都使 i 移到父结点，其深度减一，所以循环必定终止。

结束时，或者 i = 1，当前元素已到根；或者父结点不小于当前元素。唯一可能的违背因此消除，整个有效区域重新满足最大堆性质。

算法只增大指定元素的关键字并交换位置，保留其他元素和堆大小，故完成了所要求的操作。最多沿一条路径走到根，时间上界为 $O(\lg n)$。

## 6.5-6 用下移父结点代替交换

**题意：** 借鉴插入排序，减少 HEAP-INCREASE-KEY 中每次交换的赋值次数。

一次普通交换一般需要三次赋值。由于目标值已经保存在参数 key 中，可以把当前位置看作空位，每轮只将父结点下移，找到位置后再填入 key。

```text
HEAP-INCREASE-KEY(A, i, key)
    if key < A[i]
        error "新关键字小于原关键字"

    while i > 1 and A[PARENT(i)] < key
        A[i] = A[PARENT(i)]
        i = PARENT(i)

    A[i] = key
```

“一次赋值”指每轮只需一次数组元素赋值 A[i] = A[PARENT(i)]；更新下标 i 仍需赋值，循环结束也需要一次填入 key 的操作。

例如插入 10 时，原路径上的父结点为 15、9、8：先将 8 下移，再将 9 下移，最后把 10 填到 15 的下方。和逐次交换的最终结果相同。

时间上界仍为 $O(\lg n)$，改进的是元素搬运次数。

## 6.5-7 用优先队列实现队列与栈

**题意：** 利用优先队列分别实现先进先出队列与后进先出栈。

关键字采用加入顺序，而非元素本身的值。为每个容器维护独立的递增计数器 t，初始为 0；每次插入时增加 1，取出元素时不减少。结点保存 (key, value)，比较只看 key。

### 队列：用最小优先队列取最早加入者

```text
ENQUEUE(Q, x)
    Q.t = Q.t + 1
    将记录 (key = Q.t, value = x) 插入最小优先队列 Q

DEQUEUE(Q)
    e = HEAP-EXTRACT-MIN(Q)
    return e.value
```

任意时刻，尚未取出的元素中最早加入者的序号最小，因此 EXTRACT-MIN 实现先进先出。

### 栈：用最大优先队列取最后加入者

```text
PUSH(S, x)
    S.t = S.t + 1
    将记录 (key = S.t, value = x) 插入最大优先队列 S

POP(S)
    e = HEAP-EXTRACT-MAX(S)
    return e.value
```

任意时刻，尚未取出的元素中最后加入者的序号最大，因此 EXTRACT-MAX 实现后进先出。

例如依次加入 A、B、C，关键字为 1、2、3，队列取出 A、B、C，栈取出 C、B、A。计数器持续递增，使插入、取出交替进行时也保持正确顺序；理论分析假设计数器不会溢出。

二叉堆实现的插入、取出时间上界均为 $O(\lg n)$。普通队列与栈可用其他结构实现常数时间操作，本题重点是用关键字编码所需顺序。

## 6.5-8 删除任意指定结点

**题意：** 对最大堆设计 HEAP-DELETE(A, i)，在 $O(\lg n)$ 时间内删除下标 i 处的元素。

### 删除目标与补位方法

只需删除指定的那个元素，保留其他元素，并让剩余元素重新构成最大堆；其他元素可以移动，不必维持原来的下标。

用末尾元素补到 i 处，再将 heap-size 减一，可以保持完全二叉树形状。若删除的就是末尾叶结点，则直接缩小堆即可。

### 为什么需要判断调整方向

设被删除的旧值为 x，补位值为 y。原来父结点不小于 x，x 又不小于孩子。

- 若 y > x，则 y 仍不小于孩子，只可能超过父结点，向上调整。
- 若 y <= x，则 y 仍不大于父结点，只可能小于孩子，向下调整。若该位置是根，则没有父结点需要检查。

删除末尾叶结点不会破坏其余父子关系，补位位置的左右子树仍分别是最大堆，因此可以在向下分支中调用 MAX-HEAPIFY。

```text
HEAP-DELETE(A, i)
    // 假设 1 <= i <= A.heap-size
    if i == A.heap-size
        A.heap-size = A.heap-size - 1
        return

    key = A[A.heap-size]
    A.heap-size = A.heap-size - 1

    if key > A[i]
        HEAP-INCREASE-KEY(A, i, key)
    else
        A[i] = key
        MAX-HEAPIFY(A, i)
```

在向上分支中，A[i] 尚未被覆盖，仍是旧值，HEAP-INCREASE-KEY 负责改值并向上调整。

### 两种方向的例子

以下例子分别从各自的初始堆开始：

| 情形 | 初始最大堆 | 删除位置 | 补位并调整后的最大堆 |
|---|---|---|---|
| 向上 | `20, 10, 18, 5, 8, 15, 17` | i = 4，删除 5 | `20, 17, 18, 10, 8, 15` |
| 向下 | `20, 18, 10, 17, 15, 8, 5` | i = 2，删除 18 | `20, 17, 10, 5, 15, 8` |

第一例中，补位的 17 超过父结点 10；第二例中，补位的 5 小于孩子 17、15。调整有时也会立即停止，不一定发生交换。

**正确性：** 补位只影响该位置的父子关系，按新旧值选择的方向能修复所有可能的违背。缩小堆保持完全二叉树形状，且剩余元素恰好为原元素集合移除目标元素的一次出现。

除常数次操作外，只调用一次向上或向下调整，所以时间上界为 $O(\lg n)$。不能一律只调用 MAX-HEAPIFY，否则无法修复第一例中与父结点的违背。

## 6.5-9 用最小堆进行 k 路归并

**题意：** 将 k 个有序链表合并为一个有序链表，所有链表的元素总数为 n，要求时间复杂度为 $O(n\lg k)$。

假设各输入链表均按非降序排列。每条链表的第一个剩余结点，是该链表所有剩余元素中的最小值。因此，全局最小值一定在这些候选结点中。

### 算法

最小堆只保存每条非空链表当前的第一个剩余结点，以结点值为关键字。每次取出堆顶，将其值追加到结果，再将该结点的后继放入堆。

```text
MERGE-K-LISTS(L₁, L₂, ..., Lₖ)
    H = 收集所有非空输入链表的首结点
    BUILD-MIN-HEAP(H)
    result = 空链表，并维护尾指针

    while H.heap-size > 0
        x = HEAP-EXTRACT-MIN(H)
        将 x.value 追加到 result 尾部
        if x.next != NIL
            MIN-HEAP-INSERT(H, x.next)

    return result
```

这里将堆推广为保存结点记录，以结点值比较，并保留 next 指针。插入实现可在末尾放入新结点记录后直接向上调整，不必对实际结点对象写入数值无穷大。结果通过复制值构造新结点，输入链表不变；维护尾指针使每次追加耗时 $O(1)$。

例如：

```text
L₁: 1 → 4 → 7
L₂: 2 → 5 → 8
L₃: 3 → 6 → 9
```

候选值起初为 {1, 2, 3}；输出 1 后补入 4，变为 {2, 3, 4}；输出 2 后补入 5，变为 {3, 4, 5}，如此继续。这里的集合只表示候选值，不表示堆数组整体有序。

### 正确性

每轮开始时，堆中恰好包含每条尚未耗尽链表的第一个剩余结点。各链表其余结点不小于自己的候选结点，所以堆顶是所有未输出元素中的最小值。

将其追加到结果，保证结果继续非降序排列；补入同一链表的后继，恢复候选集合的性质。每轮输出一个结点，最终所有 n 个元素都恰好输出一次。相等关键字可以任意选择，仍能保证数值有序。

### 复杂度

堆中每条链表最多贡献一个结点，因此堆大小最多为 k。扫描链表表头并建堆耗时 $O(k)$，每个元素入堆、出堆各一次。

在通常的 $2\le k\le n$ 情形下，总时间为

$$
O(k+n\lg k)=\boxed{O(n\lg k)}.
$$

若允许空链表或 k = 1，更一般的统一上界可以写为 $O(k+n\lg(k+1))$；只有一条非空输入链表时，复制输出只需线性时间。不能在 k = 1 时把 $\lg1=0$ 机械理解为零运行时间。

堆所需额外空间为 $O(k)$，新建的输出链表另占 $O(n)$ 空间。不把全部 n 个元素放入堆，才能把每次选择的代价限制在 $O(\lg k)$。
