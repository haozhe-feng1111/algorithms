# 6.2 维护堆的性质

本节整理《算法导论》第三版习题 6.2-1 至 6.2-6。先回顾 MAX-HEAPIFY 的前提和下沉过程，再记录逐题解答与易错点。题意按学习讨论简述，伪代码为整理后的等价写法。

## 小节回顾

### 最大堆性质与数组下标

最大堆要求每个非根结点的值不大于父结点的值，不要求左右孩子之间有序。

数组下标从 1 开始，结点 $i$ 的左右孩子下标为

$$
\operatorname{LEFT}(i)=2i,\qquad \operatorname{RIGHT}(i)=2i+1.
$$

记 $n=A.\text{heap-size}$。只有下标不超过 $n$ 的孩子才存在。`heap-size` 表示当前堆包含的元素个数，不一定等于整个数组的长度。

### MAX-HEAPIFY 的前提和目标

**调用前提：** $1\le i\le n$，以 $i$ 的左右孩子为根的子树均已是最大堆，但 $A[i]$ 可能太小。

**目标：** 恢复以 $i$ 为根的整棵子树的最大堆性质。

算法比较当前结点和存在的两个孩子：若当前结点已经最大，则结束；否则，与较大的孩子交换，再到该孩子的位置继续修复。被下沉的元素沿一条路径向下移动。

```text
MAX-HEAPIFY(A, i)
    l = LEFT(i)
    r = RIGHT(i)
    largest = i

    if l ≤ A.heap-size and A[l] > A[largest]
        largest = l

    if r ≤ A.heap-size and A[r] > A[largest]
        largest = r

    if largest ≠ i
        exchange A[i] with A[largest]
        MAX-HEAPIFY(A, largest)
```

这里的 `and` 按短路求值理解：先确认孩子存在，再访问对应的数组元素。

**为什么要选较大的孩子？** 换到父结点位置的值必须同时不小于两个孩子。只选一个比父结点大的孩子，仍可能留下违反最大堆性质的父子关系。

交换后，上方的父子关系得到修复；原来较大孩子的子树中，只有新根可能太小，因此满足下一次递归的前提。

### 运行时间

每次调用除递归外只做常数次操作，每次递归下降一层。堆高为 $\lfloor\lg n\rfloor$，因此最坏运行时间为 $O(\lg n)$（渐近讨论取 $n\ge2$）；若不必下沉，则为 $\Theta(1)$。习题 6.2-6 将证明最坏情况的下界，从而得到紧确界 $\Theta(\lg n)$。

## 6.2-1 给定数组的下沉过程

**题意：** 对数组

$$
A=\langle27,17,3,16,13,10,1,5,7,12,4,8,9,0\rangle
$$

执行 `MAX-HEAPIFY(A, 3)`，说明操作过程。这里 $A.\text{heap-size}=14$。

**解答：** 下标 3 对应的子树初始为

```text
          3                 下标 3
        /   \
      10     1              下标 6、7
     /  \   /
    8    9 0                下标 12、13、14
```

左右子树分别满足最大堆性质，但根的值 $3$ 太小。

1. 比较 $A[3]=3$、$A[6]=10$、$A[7]=1$，最大者是 $A[6]$。交换下标 3 和 6 的元素，继续检查下标 6。
2. 比较 $A[6]=3$、$A[12]=8$、$A[13]=9$，最大者是 $A[13]$。交换下标 6 和 13 的元素，继续检查下标 13。
3. 下标 13 是叶结点，没有孩子，结束。

两次交换后的数组依次为

```text
初始：       ⟨27,17, 3,16,13,10,1,5,7,12,4,8,9,0⟩
交换 3、6：  ⟨27,17,10,16,13, 3,1,5,7,12,4,8,9,0⟩
交换 6、13： ⟨27,17,10,16,13, 9,1,5,7,12,4,8,3,0⟩
```

最终子树为

```text
         10
        /  \
       9    1
      / \  /
     8   3 0
```

因此最终结果是

$$
\boxed{A=\langle27,17,10,16,13,9,1,5,7,12,4,8,3,0\rangle.}
$$

元素 $3$ 的下沉路径为下标 $3\to6\to13$。

**易错点：** 第二次不能让 $3$ 与 $8$ 交换，否则会得到父结点为 $8$、右孩子为 $9$ 的局部结构，仍违反最大堆性质。

## 6.2-2 维护最小堆

**题意：** 写出 MIN-HEAPIFY 的伪代码，并比较它与 MAX-HEAPIFY 的运行时间。

**思路：** 最小堆要求父结点不大于孩子。将寻找最大值改为寻找最小值，每次与较小的孩子交换即可。

```text
MIN-HEAPIFY(A, i)
    l = LEFT(i)
    r = RIGHT(i)
    smallest = i

    if l ≤ A.heap-size and A[l] < A[smallest]
        smallest = l

    if r ≤ A.heap-size and A[r] < A[smallest]
        smallest = r

    if smallest ≠ i
        exchange A[i] with A[smallest]
        MIN-HEAPIFY(A, smallest)
```

**调用前提：** 左右子树均已是最小堆，只有当前根结点可能太大。

**运行时间：** 两者每层都只做常数次操作，且每次最多下降一层。因此渐近运行时间相同：最好情况为 $\Theta(1)$，最坏情况为 $\Theta(\lg n)$。对 MIN-HEAPIFY 的下界，可将 6.2-6 中的大小关系反转。

## 6.2-3 当前结点已经比孩子都大

**题意：** 如果 $A[i]$ 比它的孩子的值都大，调用 MAX-HEAPIFY 会怎样？

**解答：** 比较后 `largest` 仍为 $i$，所以不会交换，也不会继续递归，数组保持不变，运行时间为 $\Theta(1)$。

**注意：** “什么都不做”是指不改变数组，算法仍然会执行边界判断和比较。若 $A[i]$ 只是大于或等于所有孩子，结论也相同。

## 6.2-4 当前结点是叶结点

**题意：** 当 $i>A.\text{heap-size}/2$ 时，调用 MAX-HEAPIFY 会怎样？

**解答：** 假设 $i$ 是堆内的合法下标，令 $n=A.\text{heap-size}$。由

$$
i>\frac n2\quad\Rightarrow\quad2i>n
$$

可知左孩子不存在，右孩子 $2i+1$ 也不存在。因此 $i$ 是叶结点。

两个孩子的边界判断均不通过，`largest` 仍为 $i$。算法不交换、不递归，数组保持不变，运行时间为 $\Theta(1)$。

**与 6.2-3 的区别：** 6.2-3 中即使有孩子，也因当前值已经足够大而停止；本题则因没有孩子而停止。叶结点的下标范围为 $\lfloor n/2\rfloor+1,\ldots,n$。

## 6.2-5 用循环代替递归

**题意：** 使用循环控制结构重写 MAX-HEAPIFY，避免递归调用。

**思路：** 交换后，被下沉的元素从位置 $i$ 移到了位置 `largest`。将 `i` 更新为 `largest`，进入下一轮循环，即可代替递归调用。

```text
MAX-HEAPIFY(A, i)
    while true
        l = LEFT(i)
        r = RIGHT(i)
        largest = i

        if l ≤ A.heap-size and A[l] > A[largest]
            largest = l

        if r ≤ A.heap-size and A[r] > A[largest]
            largest = r

        if largest == i
            return

        exchange A[i] with A[largest]
        i = largest
```

**正确性说明：** 每轮开始时，当前位置的左右子树都是最大堆，只有当前根可能太小。若当前结点已经最大，整棵当前子树满足最大堆性质，算法结束；否则，交换修复上方关系，潜在问题移到 `largest` 位置，更新 $i$ 后继续。此前修复的祖先关系不会被后续下沉破坏。每次交换都向下移动一层，最终必在某个已满足条件的结点或叶结点停止。

### 为什么循环版可能更高效？

递归版每次下沉都调用一次函数，通常需要保存返回位置、管理参数和调用栈。循环版在交换后只需执行 `i = largest`，再开始下一轮，避免重复的函数调用开销。

两者的比较、交换和下沉路径相同。时间上的改进主要是减少常数开销，时间复杂度的阶没有改变。

| 比较项 | 递归版 | 循环版 |
|---|---|---|
| 最坏时间复杂度 | $\Theta(\lg n)$ | $\Theta(\lg n)$ |
| 辅助空间 | 未做尾调用优化时，最坏 $\Theta(\lg n)$ | $\Theta(1)$ |
| 每次下沉的函数调用开销 | 通常有 | 没有递归调用 |

这里的递归属于尾递归：递归调用返回后，当前调用没有其他操作要做。若编译器能将尾递归优化成循环，递归版也可能达到常数辅助空间，并获得接近循环版的效率。因此不能断言循环版在所有编译器下都更快。

**易错点：** `i = largest` 是改变下一轮检查的下标；下标本身没有随元素交换而移动。每轮都必须重新计算左右孩子，并重置 `largest = i`。

## 6.2-6 最坏运行时间的下界

**题意：** 证明大小为 $n$ 的堆上，MAX-HEAPIFY 的最坏情况运行时间为 $\Omega(\lg n)$。

**思路：** 上界说明最多需要多少时间；证明最坏情况的下界，需要构造一种合法输入，让算法确实沿着一条长路径下沉。

**证明：**

先构造一个有 $n$ 个结点、元素互不相同的最大堆。例如令 $A[j]=n-j+1$，由于父结点下标小于孩子下标，父结点的值严格大于孩子的值。

再把根结点改成 $0$。此时左右子树均未改变，仍是最大堆，因此满足 `MAX-HEAPIFY(A, 1)` 的调用前提；根的值则比其余元素都小。

调用后，元素 $0$ 只要还有孩子，就一定与较大的孩子交换，继续下沉，直到某个叶结点。

设堆高为 $h=\lfloor\lg n\rfloor$。由完全二叉树的形状，叶结点只可能位于深度 $h$ 或 $h-1$（$h\ge1$ 时）。因此元素 $0$ 至少下沉 $h-1$ 条边。对于 $n\ge4$，有 $h\ge2$ 且

$$
h-1\ge\frac h2=\Omega(\lg n).
$$

每层均需常数时间，所以该输入的运行时间为 $\Omega(\lg n)$，从而最坏情况运行时间满足

$$
\boxed{T_{\mathrm{worst}}(n)=\Omega(\lg n).}
$$

结合本节的上界 $O(\lg n)$，得到

$$
\boxed{T_{\mathrm{worst}}(n)=\Theta(\lg n).}
$$

**理解与易错点：**

- 树高按边数计算。每层都填满时，有 $n=2^{h+1}-1$，即 $h=\lg(n+1)-1$，不能把层数与高度直接混为一谈。
- 一般的完全二叉树中，叶结点不一定都在最底层，但其深度仍为 $\Theta(\lg n)$，不影响下界证明。
- 仅说“树高为 $\Theta(\lg n)$”不足以证明运行时间下界，还需说明存在输入迫使算法走过这么长的路径。
- 上述构造覆盖任意足够大的 $n$，不只限于每层都填满的堆。
- 下界针对最坏情况，不表示每次调用都需要 $\Omega(\lg n)$ 时间；6.2-3 和 6.2-4 就只需要 $\Theta(1)$。

## 本节复习提纲

| 题号 | 核心结论 | 关键方法 |
|---|---|---|
| 6.2-1 | 元素 $3$ 沿下标 $3\to6\to13$ 下沉 | 每次与较大的孩子交换 |
| 6.2-2 | MIN-HEAPIFY 与 MAX-HEAPIFY 渐近时间相同 | 将大小关系反转 |
| 6.2-3 | 当前结点已足够大时，不交换、不递归 | 比较后 `largest = i` |
| 6.2-4 | 叶结点无需下沉 | 用 $2i>n$ 判断孩子不存在 |
| 6.2-5 | 循环减少调用开销，并使用常数辅助空间 | 交换后令 `i = largest` |
| 6.2-6 | 最坏运行时间为 $\Theta(\lg n)$ | 构造最小元素从根下沉到叶结点 |

与下一节的联系：维护堆的过程以“左右子树已经是堆”为前提，后续自底向上建堆正是利用这一点，依次修复各个非叶结点。
