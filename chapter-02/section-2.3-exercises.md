## 小节回顾

### 分治法的三个步骤

分治法将原问题拆成规模更小的同类问题，递归求解，再利用子问题的解得到原问题的解。

1. **分解：** 将原问题分成若干子问题。
2. **解决：** 递归求解；规模足够小时直接处理。
3. **合并：** 将子问题的解组合成原问题的解。

归并排序将数组按位置分成左右两半，分别递归排序，最后合并。分解时不调整元素顺序；到单元素数组时，它天然有序，然后才开始从下往上合并。

### MERGE-SORT 与 MERGE 的区别

| 名称 | 作用 | 输入需要已经有序吗？ |
|---|---|---|
| `MERGE-SORT`，归并排序 | 分解数组、递归排序两半、调用合并过程 | 不需要 |
| `MERGE`，合并 | 将两个已经分别有序的相邻数组段合成一个有序段 | 两段必须各自有序 |

`MERGE(A, p, q, r)` 合并 $A[p\ldots q]$ 和 $A[q+1\ldots r]$，结果写回 $A[p\ldots r]$。

例如，将 `[3, 41]` 和 `[26, 52]` 合并成 `[3, 26, 41, 52]`，就是执行一次 MERGE。每次只比较两边尚未取出部分的首元素，取出较小者；因为两边各自有序，这也是全部剩余元素中的一个最小值。

本笔记下标从 1 开始，`=` 表示赋值，`==` 表示相等判断，`NIL` 表示未找到。逻辑条件 `and` 按从左到右的短路方式求值。

```text
MERGE-SORT(A, p, r)
    if p < r
        q = floor((p + r) / 2)
        MERGE-SORT(A, p, q)
        MERGE-SORT(A, q + 1, r)
        MERGE(A, p, q, r)
```

### 归并排序的运行时间

当 $n$ 是 2 的幂时，排序两半需要 $2T(n/2)$，合并需要 $\Theta(n)$，因此

$$
T(n)=2T(n/2)+\Theta(n),\qquad T(1)=\Theta(1).
$$

递归树每个合并层的总工作量为 $\Theta(n)$，合并层数为 $\lg n$，再计入叶结点的总代价 $\Theta(n)$，得到 $T(n)=\Theta(n\lg n)$。一般的 $n$ 分成 $\lceil n/2\rceil$ 和 $\lfloor n/2\rfloor$，结论不变。

这里的渐近递归式与 2.3-3 给定的精确递归式要区分：只有明确了基础值和每层开销，才能讨论精确等式。

## 2.3-1 展示归并排序的执行过程

**题意：** 参照教材图 2-4，展示归并排序在数组 $\langle3,41,52,26,38,57,9,49\rangle$ 上的操作。

### 自顶向下分解

```text
[3, 41, 52, 26, 38, 57, 9, 49]

[3, 41, 52, 26]                  [38, 57, 9, 49]

[3, 41]       [52, 26]           [38, 57]       [9, 49]

[3]  [41]     [52]  [26]         [38]  [57]     [9]  [49]
```

### 自底向上合并

| 合并层次 | 合并后的有序数组段 |
|---|---|
| 单元素两两合并 | `[3, 41]`；`[26, 52]`；`[38, 57]`；`[9, 49]` |
| 相邻二元素段合并 | `[3, 26, 41, 52]`；`[9, 38, 49, 57]` |
| 最后一次合并 | `[3, 9, 26, 38, 41, 49, 52, 57]` |

例如，合并 `[3, 41]` 与 `[26, 52]` 时，依次比较并取出 3、26、41，最后接上剩余的 52。

**易错点：** 分解只是按位置切开，不是在分解时排序；每次合并的两段必须已经分别有序。

## 2.3-2 不使用哨兵的 MERGE

**题意：** 重写 MERGE，不使用哨兵。当一边的真实元素全部复制回 A 后，停止两边比较，再将另一边剩余部分复制回 A。

### 原来的哨兵版本

教材在临时数组 L 和 R 末尾各添加一个 $+\infty$。这里假定所有真实元素都严格小于哨兵。

```text
MERGE-WITH-SENTINELS(A, p, q, r)
    n1 = q - p + 1
    n2 = r - q
    创建数组 L[1..n1+1]、R[1..n2+1]

    for i = 1 to n1
        L[i] = A[p + i - 1]
    for j = 1 to n2
        R[j] = A[q + j]

    L[n1 + 1] = ∞
    R[n2 + 1] = ∞
    i = 1
    j = 1

    for k = p to r
        if L[i] ≤ R[j]
            A[k] = L[i]
            i = i + 1
        else
            A[k] = R[j]
            j = j + 1
```

例如，`L = [3, 41, ∞]`，`R = [26, 52, ∞]`。取出 3、26、41 后，左侧指向 ∞，下一次比较就会取出右侧的 52，无需单独判断左边是否用完。

循环恰好写入 $r-p+1$ 个元素，所以所有真实元素取完时循环结束，不会把哨兵也写回去。

### 改写后的无哨兵版本

不再添加 ∞，改用下标判断两边是否还有元素。i、j 指向 L、R 中下一个待取元素，k 指向 A 中下一个待填位置。

```text
MERGE(A, p, q, r)
    n1 = q - p + 1
    n2 = r - q
    创建数组 L[1..n1]、R[1..n2]

    for i = 1 to n1
        L[i] = A[p + i - 1]
    for j = 1 to n2
        R[j] = A[q + j]

    i = 1
    j = 1
    k = p

    while i ≤ n1 and j ≤ n2
        if L[i] ≤ R[j]
            A[k] = L[i]
            i = i + 1
        else
            A[k] = R[j]
            j = j + 1
        k = k + 1

    while i ≤ n1
        A[k] = L[i]
        i = i + 1
        k = k + 1

    while j ≤ n2
        A[k] = R[j]
        j = j + 1
        k = k + 1
```

**正确性：** 主循环开始时，已填入的 $A[p\ldots k-1]$ 是两边已取出元素的有序合并结果，而 L[i]、R[j] 分别是两边剩余元素中的最小值。每次取较小者，保持已填入部分有序且不丢失元素。主循环结束时至少一边已空；另一边剩余部分本身有序，且不小于已输出的元素，依次接上即可。

| 哨兵版 | 无哨兵版 |
|---|---|
| 末尾添加 ∞，不显式检查是否用完 | 比较前检查两边下标 |
| 一个固定次数的合并循环 | 一个比较循环，两个收尾循环 |
| 一边用完后，哨兵让另一边持续被选中 | 一边用完后，直接复制另一边剩余元素 |

主循环结束后，至多一个收尾循环实际复制元素。三个 while 总共只向 A 写入 $n_1+n_2$ 个元素，时间仍为 $\Theta(n_1+n_2)$，临时数组空间为 $\Theta(n_1+n_2)$。相等时先取左边元素，也保留了归并排序的稳定性。

## 2.3-3 用归纳法证明递归式的精确解

**题意：** 对 $n=2^k$，证明以下递归式的解为 $T(n)=n\lg n$：

$$
T(n)=
\begin{cases}
2, & n=2,\\
2T(n/2)+n, & n=2^k,\ k>1.
\end{cases}
$$

**证明：** 对指数 $k\ge1$ 作数学归纳。

**基础情形：** $k=1$，即 $n=2$ 时，$T(2)=2=2\lg2$，成立。

**归纳步骤：** 对 $k>1$，假设规模 $n/2=2^{k-1}$ 时成立，即

$$
T(n/2)=\frac n2\lg\frac n2.
$$

代入递归式：

$$
\begin{aligned}
T(n)
&=2T(n/2)+n\\
&=2\cdot\frac n2\lg\frac n2+n\\
&=n(\lg n-1)+n\\
&=n\lg n.
\end{aligned}
$$

因此，对所有 $n=2^k$、$k\ge1$，均有 $\boxed{T(n)=n\lg n}$。

**易错点：** 本题证明的是精确等式；不能将题目给定的基础值和开销任意改写后，仍声称有同样的精确解。关键恒等式是 $\lg(n/2)=\lg n-1$。

## 2.3-4 递归插入排序的最坏时间递归式

**题意：** 先递归排序 $A[1\ldots n-1]$，再将 A[n] 插入已排序前缀。写出最坏情况运行时间的递归式。

第一步处理一个规模为 n−1 的子问题，耗时 $T(n-1)$。第二步最坏需要将前面 n−1 个元素全部右移，耗时 $\Theta(n)$。因此

$$
\boxed{
T(n)=
\begin{cases}
\Theta(1), & n=1,\\
T(n-1)+\Theta(n), & n>1.
\end{cases}
}
$$

进一步展开可得 $T(n)=\Theta(n^2)$。题目只要求递归式，这里补充结果便于比较。

**与归并排序的区别：** 插入排序处理一个 n−1 规模的子问题，之后插入一个元素；归并排序处理两个约 n/2 规模的子问题，之后合并两半。递归写法本身不会保证对数层数或更快的运行时间。

## 2.3-5 二分查找及其最坏运行时间

**题意：** 对已排序数组，写出二分查找的迭代或递归版本，并证明最坏情况运行时间为 $\Theta(\lg n)$。

### 思路与伪代码

检查当前范围的中点。如果目标小于中间元素，只查左半边；大于中间元素，只查右半边。每次排除的区域不可能包含目标，这是数组有序带来的保证。

以下版本显式接收搜索范围，便于 2.3-7 复用。查找整个数组时调用 `BINARY-SEARCH(A, x, 1, A.length)`。

```text
BINARY-SEARCH(A, x, low, high)
    while low ≤ high
        mid = low + floor((high - low) / 2)

        if A[mid] == x
            return mid
        else if A[mid] < x
            low = mid + 1
        else
            high = mid - 1

    return NIL
```

例如在 `[3, 9, 26, 38, 41, 49, 52, 57]` 中查找 26，依次检查 38、9、26，即可找到。

**正确性：** 每轮开始时，如果初始搜索范围内存在目标，则当前范围仍包含一个目标位置。比较中点后，利用有序性排除不可能含目标的半边，保持这一性质。命中时返回正确下标；范围为空时，已经排除了整个初始搜索范围，因此返回 NIL 正确。

### 最坏时间证明

每轮进行常数次操作，且剩余规模至多为原来的一半。初始范围有 n 个元素时，第 t 轮结束后至多剩 $\lfloor n/2^t\rfloor$ 个元素，因此至多进行 $\lfloor\lg n\rfloor+1$ 轮，得到上界 $O(\lg n)$。

为证明下界，令目标值大于所有数组元素。按上述向下取整的中点写法，每轮都保留右半边，其大小恰好是当前规模的一半向下取整。于是需要 $\lfloor\lg n\rfloor+1$ 轮才会清空范围，得到最坏情况下界 $\Omega(\lg n)$。因此，对 $n\ge2$，

$$
\boxed{T_{\mathrm{worst}}(n)=\Theta(\lg n)}.
$$

**易错点：**

- 中点已检查且不匹配后，用 `mid + 1` 或 `mid - 1` 排除它，保证范围缩小。
- `low > high` 表示范围为空，查找失败；空范围会直接返回 NIL。
- 最好情况在第一次命中，时间为 $\Theta(1)$。
- 二分查找只继续处理一半，递归版本的时间可写为 $T(n)=T(\lfloor n/2\rfloor)+\Theta(1)$ 的最坏情况递归式；归并排序则要处理两半，具有系数 2。

## 2.3-6 用二分查找能否加速插入排序到 n lg n？

**题意：** 将插入排序中寻找插入位置的线性查找改成二分查找，能否使最坏运行时间变为 $\Theta(n\lg n)$？

**结论：不能。** 找位置可以变快，但在普通数组中为插入腾出位置仍需要移动元素。

### 每轮只插入一个元素

每轮取出一个待处理元素，在已有序前缀中进行一次二分查找，确定插入位置，再右移相关元素并放入当前元素。有序前缀每轮扩大一个元素。

例如，对 `[5, 4, 3, 2, 1]` 排序，竖线左侧表示已有序的前缀：

```text
[5 | 4, 3, 2, 1]
[4, 5 | 3, 2, 1]       插入 4，移动 1 个元素
[3, 4, 5 | 2, 1]       插入 3，移动 2 个元素
[2, 3, 4, 5 | 1]       插入 2，移动 3 个元素
[1, 2, 3, 4, 5 | ]     插入 1，移动 4 个元素
```

这里的“多次二分查找”是不同插入轮次各查一次；每次二分查找内部又可能经过多轮比较。并不是一次二分查找就把所有元素插入。

### 为什么总移动次数为平方量级

对于元素互异的逆序输入，第 j 轮处理 A[j] 时，它比前面所有元素都小，需要移动 j−1 个元素。总右移次数为

$$
\sum_{j=2}^{n}(j-1)
=1+2+\cdots+(n-1)
=\frac{n(n-1)}2
=\frac12n^2-\frac12n
=\Theta(n^2).
$$

不是每轮移动 $n^2$ 次，也不是总共恰好移动 $n^2$ 次；精确的总右移次数是 $n(n-1)/2$，其增长量级为平方。

二分查找使寻找位置的总最坏开销变为 $\Theta(n\lg n)$，但移动仍需 $\Theta(n^2)$，因此整个排序的最坏时间仍为 $\boxed{\Theta(n^2)}$。

**易错点：** 比较次数减少，不代表总运行时间也降到同样的量级。原插入排序在向左查找时同时右移元素；改用二分查找后，查找与移动分开了，但移动工作依然存在。

## ★2.3-7 排序与二分查找解决两数之和

**题意：** 给定含 n 个整数的集合 S 和整数 x，设计一个 $\Theta(n\lg n)$ 时间算法，判断 S 中是否存在两个不同元素，其和为 x。

### 思路与伪代码

先用归并排序将元素排成数组 A。依次固定 A[i]，在右侧 $A[i+1\ldots n]$ 中二分查找补数 $x-A[i]$。找到就返回 TRUE，否则全部检查后返回 FALSE。

只搜索右侧，既避免同一个元素被使用两次，也避免重复检查同一对。

```text
TWO-SUM(S, x)
    A = 将 S 中的元素放入数组
    n = A.length
    if n < 2
        return FALSE

    MERGE-SORT(A, 1, n)

    for i = 1 to n - 1
        j = BINARY-SEARCH(A, x - A[i], i + 1, n)
        if j ≠ NIL
            return TRUE

    return FALSE
```

例如，$S=\{8,3,6,1\}$、x=9。排序得到 `[1, 3, 6, 8]`，固定 1 后查找补数 8，找到即可返回 TRUE。

### 正确性

- **返回 TRUE 时：** 找到了 $j>i$ 且 $A[j]=x-A[i]$，所以两个不同位置的元素之和确实为 x。
- **存在答案时：** 设排序后的某对答案下标为 $i<j$。当外层循环处理 i 时，A[j] 位于右侧搜索范围中，二分查找一定会找到补数；若此前已经返回 TRUE，也已经找到了有效答案。因此不会漏解。

只在整个数组中查找补数而不检查位置，可能错误地将一个元素使用两次。例如 $S=\{1,3\}$、x=6，不能用唯一的 3 与自身相加。限制搜索范围到右侧即可避免这一问题。

### 运行时间

按通常的基本运算常数时间模型，对 $n\ge2$：

- 将元素放入数组需要 $\Theta(n)$。
- 归并排序需要 $\Theta(n\lg n)$。
- 至多进行 n−1 次二分查找，每次至多 $O(\lg n)$，合计 $O(n\lg n)$。

总时间为 $\boxed{\Theta(n\lg n)}$。其中排序已经给出同阶下界，所以即使查找阶段提前返回，也不影响本算法的这一渐近结论。
